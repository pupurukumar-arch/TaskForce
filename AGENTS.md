# Project contribution rules

- Do not create new files without the user's explicit permission.
- Do not refactor, reorganize, or modify unrelated code.
- Preserve the current folder and module structure.
- Make the smallest change that solves the requested problem.
- Ask for approval before adding or updating dependencies.
- Keep secrets in `.env`; never commit or expose them.
- Run relevant checks after changes and report the files changed.
- Keep this as a B.Tech placement project: prefer simple, industry-recognized features that the project owner can explain and defend in an interview.
- Use clear REST APIs, modular controllers/routes/models, JWT authentication, validation, documentation, and practical security basics before considering advanced architecture.
- Do not add complex infrastructure, design patterns, cloud services, microservices, or dependencies unless the user explicitly asks for them and understands why they are needed.
- When adding a feature, explain in plain language what it does, why it is useful, and how it works in this project.
